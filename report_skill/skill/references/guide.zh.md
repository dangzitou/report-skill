# 日报 / 周报写作指南

> 来源：整理自小红书上 20+ 篇高赞职场笔记（大厂产品、研发主管、实习转正经验帖），以及金字塔原理 / PREP / SCQA 等经典汇报方法。
> 这份指南同时是 report-skill 调用 AI 时的「写作规范」。

## 0. 先搞清楚领导在读什么

- **领导只有 30 秒。** 他同时管很多人，不会逐字读。他扫一眼，只想知道三件事：**进度、问题、计划**。
- **表达能力 = 可见度。** 很多人不是没做好，而是没被看见。领导看不到你每天的细节，周报就是他了解你的主要渠道。
- **领导要的是安全感。** 让他确信：事情在推进，风险看得见，而且有人在管。所以“平稳”“推进中”这种词等于没写；“本周没出一次线上故障”才让他睡得着。
- **首因效应。** 第一句话决定印象，最重要的结论必须放在第一行。
- **让领导做选择题，不做问答题。** 抛出困难却没有方案，等于把活儿推回给领导。

## 1. 日报、周报、月报：定位不同

| 类型 | 核心 | 一句话 |
| --- | --- | --- |
| 日报 | **讲事实** | 今天推进到哪、有什么风险、明天做什么。不写感悟，不拔高 |
| 周报 | **讲变化** | 和上周比，哪些推进了、哪些卡住了、出了什么新情况。**不是五天日报拼起来** |
| 月报 | **讲意义** | 带来了什么结果和价值，沉淀了什么经验，下一步怎么迭代 |

## 2. 九条铁律

1. **结论先行（PREP / 金字塔）。** 开头一句话总结全貌，然后是重点成果，最后才是细节。
2. **写结果，不写过程。** 把“做了什么”换成“做成了什么”。
   - ❌ 写了登录模块
   - ✅ 登录模块支持手机号+验证码登录，自测通过（2d）
3. **行动 + 结果 + 数据。** 能量化的就量化：数量、耗时、百分比、+/- 行数、影响范围。数字尽量往**时间和钱**上靠（省了多少、快了多少）。
4. **抓大放小，重点在前。** 最重要的项目放最前面；零碎杂活合并成一条，不要一条条罗列，否则整篇看起来都在打杂。
5. **写“挡住了什么”。** 修掉的隐患、避开的坑、没发生的事故同样是价值。
6. **问题 = 现象 → 原因 → 方案 → 需要的支持。** 最好给两个选项并说明倾向，例如“A 方案更快但有技术债，B 方案稳但多 2 天，倾向 A，需要你确认”。
7. **计划要可验收。** 只列 1–3 件事，每件都要带节点和交付物，比如“周四前完成订单模块联调，输出测试报告”，不写“继续推进”。
8. **客观，不带情绪。** 跨团队协作只陈述事实和进度，不指责、不甩锅，也不吐槽。
9. **手机友好。** 短句、序号、关键结论加粗。别写大长段。

## 3. 加分项（周报）

- **沉淀与利他：** 写了什么文档、脚本、工具，踩坑总结能给谁复用。这能体现影响力。
- **失败也有价值：** “【结论：不推荐】方案 A 在当前数据下不收敛，原因推测为……”，这样写说明你排除了一条错误路径。
- **个人成长：** 一两句即可，比如学到了什么，并且已经用在了哪里。
- **和目标对齐：** 计划尽量挂到团队 OKR 或指标上。

## 4. 红线：AI 写报告最容易翻车的地方

- **不编造。** 材料里没有的数字、结论、业务影响，一律不写，或标注 `[待确认]`。AI 负责整理事实，人负责确认事实。
- **不夸大。** 改了个参数就别写“优化了系统性能”，这种夸大领导一眼就能看穿，反而掉信任。
- **成果归属要准。** 别人做的不要写成自己的，团队成果写清楚自己负责的那一环。
- **脱敏。** 不出现密钥、密码、客户隐私和内部敏感数据。
- **别暴露“AI 味”。** 少用“赋能、抓手、闭环、全面提升”这类空话，也别连用排比句和感叹号。

## 5. 模板

### 日报（3 块就够）

```
**一句话总结**：今天完成 X，推进 Y；Z 有风险，已在处理。

**今日完成**
1. 【项目A】做成了什么（数据/证据）
2. 【项目B】……

**风险 / 需要支持**
- 现象 → 影响 → 我的方案 → 需要谁在何时前给什么支持

**明日计划**
1. 做什么 + 交付物/节点
```

### 周报（5 栏）

```
**本周概览**：本周重点围绕【X】，完成【A、B、C】，【关键数据】；【Y】进度 60%。

**重点成果**（按项目，重点在前）
**问题与思考**（现象 → 根因 → 方案/待决策）
**下周计划**（1–3 件，带节点和验收标准）
**沉淀 / 成长**（可选）
```
